Lesson 19

Knowledge Graphs and Embedding

A knowledge graph is a heterogeneous graph (Lesson 18) viewed through a specific lens: every edge is a fact, written as a triple (h, r, t) — head entity, relation, tail entity. "(Obama, born_in, Hawaii)." "(Aspirin, treats, Headache)." The graph itself is the database. The task that dominates this space isn't node classification — it's knowledge graph completion: given millions of known facts, predict plausible missing ones. Does the triple (Obama, born_in, Kenya) belong in the graph? Almost certainly not. Does (Aspirin, treats, Fever)? Probably.

This lesson is deliberately not about message passing. It's about a different, older idea — recall DeepWalk / node2vec from the shallow-embeddings lesson, where you learn a lookup-table vector per node with no neural network aggregation at all. Knowledge graph embedding (KGE) methods do the same thing for multi-relational graphs: learn a vector per entity and a vector (or matrix) per relation, such that some simple scoring function over (h, r, t) is high for true triples and low for corrupted ones.

Key idea: KGE methods don't aggregate neighbor messages the way GCN/GAT/GraphSAGE do. They learn shallow embeddings directly, optimized so a scoring function f(h, r, t) separates true triples from corrupted ones. The relation itself becomes a learned object in the embedding space — not just a parameterization choice for a weight matrix, as it was for R-GCN in Lesson 18.

TransE: relations as translations

TransE (Bordes et al., 2013) has arguably the simplest idea in the whole GNN/graph-representation-learning space: if (h, r, t) is true, the tail's embedding should be reachable from the head's embedding by adding the relation vector:

h + r ≈ t
score(h, r, t) = -‖ h + r - t ‖

TransE is trained with a margin-based ranking loss: true triples should score higher than corrupted ones (formed by swapping in a random head or tail) by at least some margin. It's cheap, scales to huge knowledge graphs, and works well for one-to-one relations. But the translation picture breaks down for relational patterns that are common in real knowledge graphs:

  • Symmetric relations (e.g., is_married_to): if h + r ≈ t and t + r ≈ h both hold, adding the two gives 2r ≈ 0, forcing r toward the zero vector — which then can't distinguish this relation from any other near-zero relation.
  • One-to-many / many-to-one relations (e.g., born_in, where many people share a birth country): TransE wants h + r to land at one specific point, but many valid tails would need to sit at that same point, collapsing entities that should stay distinct.

DistMult: a bilinear score

DistMult replaces translation with a bilinear form. Each relation is a diagonal matrix (equivalently, a vector r, since only the diagonal is used), and the score is:

score(h, r, t) = hT diag(r) t = ∑i hi ri ti

This is cheap (elementwise multiply-then-sum, no full matrix) and empirically strong. But look closely at the formula: swapping h and t leaves the score completely unchanged, since elementwise multiplication commutes. That means DistMult is fundamentally symmetric — it cannot represent antisymmetric relations like parent_of, where (A, parent_of, B) being true should make (B, parent_of, A) false. DistMult would score both triples identically.

ComplEx: moving to complex-valued embeddings

ComplEx (Trouillon et al., 2016) fixes exactly this gap by embedding entities and relations as complex vectors instead of real ones, and scoring with the real part of a Hermitian (conjugated) inner product:

score(h, r, t) = Re( ∑i hi ri conj(ti) )

The conjugate on t is what breaks the symmetry that trapped DistMult: swapping h and t no longer leaves the score unchanged, because conjugation is applied to whichever embedding sits in the tail position. This lets a single, still-simple bilinear-style model represent both symmetric and antisymmetric relations, which is why ComplEx (and its later relatives) generally outperforms both TransE and DistMult on standard knowledge graph completion benchmarks.

Analogy: Going from DistMult to ComplEx is the same trick as going from a real-valued to a complex-valued rotation matrix in signal processing — the complex domain gives you a natural notion of "direction" (phase) that a purely real, symmetric bilinear form can't express.
Model Scoring intuition Weak spot
TransE h + r ≈ t (translation) Symmetric & many-to-many relations
DistMult hTdiag(r)t (bilinear, real) Antisymmetric relations
ComplEx Re(hTdiag(r)conj(t)) (bilinear, complex) More parameters, still no explicit composition

Where this reconnects to message passing

These three methods are all "shallow" — no neighborhood aggregation, just a lookup-table embedding per entity and per relation. In practice, KGE and GNN ideas combine: R-GCN from Lesson 18 is often used as an encoder that produces entity embeddings via relational message passing, which then feed into a DistMult-style decoder for the actual link-prediction score. The GNN handles structural context; the shallow scoring function handles the final triple-plausibility judgment. This encoder/decoder split is worth remembering — it reappears whenever a graph task needs both "understand the neighborhood" and "score a specific relationship."

Check your understanding

1. Why does TransE struggle to represent a symmetric relation like "is_married_to"?

  • It forces the relation vector to zero
  • It forces the entity vectors to align
  • It forces the embedding dimension to shrink
  • It forces the loss function to diverge
If h + r ≈ t and t + r ≈ h both need to hold, adding them gives 2r ≈ 0, pushing the relation vector toward zero and making it indistinguishable from other near-zero relations.

2. What's the essential change that lets ComplEx model antisymmetric relations, unlike DistMult?

  • ComplEx uses complex-valued embeddings with a conjugate operation
  • ComplEx uses larger embeddings with more training data
  • ComplEx uses graph convolutions with additional attention layers
  • ComplEx uses random negative sampling with harder examples
DistMult's bilinear score is symmetric in h and t, so it can never separate a true triple from its reversed form. ComplEx embeds in complex space and conjugates the tail embedding, which breaks that symmetry and lets the model score (A, parent_of, B) differently from (B, parent_of, A).

3. In knowledge graph completion, what does the trained scoring function let us do?

  • Rank candidate tail entities for a triple
  • Rank candidate node degrees for a graph
  • Rank candidate edge counts for a batch
  • Rank candidate loss values for a model
Given a partial triple (h, r, ?), the scoring function is evaluated against every candidate entity as the tail, and the candidates are ranked by score. High-ranked, unseen triples are the model's proposed missing facts.

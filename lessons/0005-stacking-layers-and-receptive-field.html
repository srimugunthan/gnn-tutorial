Lesson 5

Stacking Layers and the Receptive Field

Lesson 4 defined a single message-passing layer: gather from direct neighbors, aggregate, update. Lesson 3 casually referred to "L message-passing layers" without saying what L actually buys you. This lesson answers that: depth in a GNN controls exactly how far information can travel across the graph, in a way that maps directly onto something you already understand from CNNs — the receptive field.

One layer, one hop

After a single message-passing layer, node i's new embedding hi(1) is a function of hi(0) and {hj(0) : j ∈ N(i)} — itself and its immediate (1-hop) neighbors, and nothing else. A node two hops away has had zero influence on hi(1), because it never appeared in any message i received.

Two layers, two hops

Now stack a second layer. Computing hi(2) requires the layer-1 embeddings of i's neighbors: {hj(1) : j ∈ N(i)}. But each of those hj(1) was itself built from j's own 1-hop neighbors in the previous layer — which includes nodes that are two hops away from i. Information from a 2-hop neighbor reaches i indirectly, by first being folded into an intermediate neighbor's embedding, then relayed to i.

Key idea: After k layers, hi(k) is a function of every node within i's k-hop neighborhood — and, generically, of nothing farther away. This set of nodes that can possibly influence hi(k) is called i's receptive field, borrowing the term directly from CNNs: stacking k convolutional layers with 3×3 kernels grows a pixel's receptive field by one ring each time, exactly the way stacking k message-passing layers grows a node's receptive field by one hop each time.

Worked example: a 2-layer receptive field

Take a small tree rooted at a target node T, with three 1-hop neighbors (A, B, C), each of which has its own further neighbor (A1, B1, C1) two hops from T:

# layer 1: every node absorbs its direct neighbors
h_A^(1) depends on {A, T, A1}
h_T^(1) depends on {T, A, B, C}          # T's receptive field: 1 hop

# layer 2: T absorbs its neighbors' layer-1 states
h_T^(2) depends on h_A^(1), h_B^(1), h_C^(1), h_T^(1)
        = depends on {T, A, B, C, A1, B1, C1}   # T's receptive field: 2 hops

Notice A1 never appears directly in any message T receives — it enters only because it was already baked into hA(1) by the time T reads it. This chaining is exactly why depth matters: each additional layer lets information relay one hop further before it reaches T.

The computation graph

Unrolling this by hand, as above, produces a tree rooted at the target node — T's computation graph. This is a genuinely useful way to think about any single node's forward pass: it's a k-layer-deep tree where the root is the node you care about, and the leaves are its k-hop neighbors. (Distill's "Understanding Convolutions on Graphs" frames the same idea as repeatedly applying a 1-hop localized convolution K times to grow the effective receptive field to K hops — identical idea, spatial-convolution framing.)

How deep should you go?

More hops sounds strictly better — more context should mean a better-informed prediction — but two practical constraints push back:

  • Cost. A node's k-hop receptive field can grow exponentially with the graph's branching factor (average degree). For a node with degree d, a naive k-hop expansion touches up to O(dk) nodes — this is why GraphSAGE (Lesson 8) samples a fixed number of neighbors per layer rather than using the full neighborhood.
  • Diminishing (and eventually harmful) returns. Real-world graphs are often "small-world": most node pairs are separated by surprisingly few hops, so a handful of layers (commonly 2–4) already covers most of the graph. Pushing depth further doesn't just get expensive — it actively degrades quality, which is Lesson 6's entire subject.
Analogy: This mirrors the CNN depth-vs-receptive-field trade-off you already know, but with a twist: an image's grid has a fixed branching factor (a 3×3 kernel always looks at 8 neighbors), so a CNN's receptive field grows predictably and linearly in area. A graph's degree varies node to node, so the receptive field's growth rate is irregular and can explode for high-degree "hub" nodes — something images never have to deal with.

Check your understanding

1. In the worked tree example, why does node A1's feature influence h_T after 2 layers but not after 1 layer?

  • It reaches T only via A's layer-1 state
  • It reaches T only via T's own features
  • It reaches T only via a self-loop edge
  • It reaches T only via the readout step
A1 is two hops from T. After layer 1, A1's feature has only been folded into A's embedding. Only when T aggregates A's layer-1 embedding during layer 2 does A1's information indirectly reach T.

2. Stacking a GNN to exactly k layers grows each node's receptive field to cover which set of nodes?

  • Every node within k hops
  • Every node in the graph
  • Only the k nearest edges
  • Only nodes with k neighbors
Each layer relays information one additional hop, so after k layers a node's embedding is a function of (generically) every node reachable within k hops — not the whole graph, unless the graph's diameter happens to be ≤ k.

3. Why can a node's k-hop receptive field grow far more unpredictably than a CNN pixel's receptive field?

  • Node degree varies across the graph
  • Node features vary across the graph
  • Edge weights vary across the graph
  • Layer count varies across the graph
A CNN kernel always has a fixed, uniform branching factor (e.g., 8 neighbors per pixel), so receptive field growth is predictable. A graph's degree distribution is irregular, so high-degree "hub" nodes can pull in vastly more nodes per hop than low-degree ones.

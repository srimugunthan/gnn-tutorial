Lesson 17

Graph Transformers

Lesson 16 placed the Transformer on the geometric map as a GNN operating on the complete graph — every token attends to every other token, with no structural bias at all. That placement raises the obvious question: if a Transformer already generalizes over an arbitrary set with full attention, why not just run it directly on a graph's nodes and let attention learn whatever structure matters? This lesson works through why that naive move fails, what has to be added back, and how the resulting graph transformers trade off against the message-passing GNNs you already know.

What plain self-attention throws away

Feed a graph's node features into a standard Transformer layer with no further changes, and every node attends to every other node with weights computed purely from feature similarity — the edge set edge_index never enters the computation. The result is provably weaker than message passing, not just structurally naive: a self-attention layer over a bag of node features, with no positional or structural information attached, is a permutation-equivariant function of the node set alone. It cannot tell a densely-connected graph from an empty one if the node features are the same, because it has no mechanism to look at the edges at all. Formally, "naked" graph transformers of this kind collapse to the same expressive class as DeepSets-style set functions — strictly weaker than 1-WL, and therefore weaker than even a single GCN layer.

Key idea: Full attention is permutation-equivariant over a set, but a graph is a set plus a structure. Dropping the structure isn't a simplification — it's a strictly weaker model than message passing, until something puts the edges back in.

Putting structure back: positional and structural encodings

The fix mirrors how vision and language Transformers handle their own domains: attach extra features to each node that encode where it sits in the graph, then let attention use them. Two schemes dominate:

  • Laplacian eigenvector positional encoding. Compute the graph Laplacian (built from the adjacency and degree matrices) and take its lowest few eigenvectors as extra coordinates for each node. These generalize the sinusoidal positional encodings of sequence Transformers — on a chain graph, the Laplacian's eigenvectors literally are sinusoids — and capture global structural position: nodes in different parts of the graph get different coordinates even if their local neighborhoods look identical.
  • Random-walk positional encoding (RWPE). For each node, record the probability that a k-step random walk started at that node returns to itself, for a range of step counts. This is cheaper to compute than an eigendecomposition and captures more local structural role — how tightly clustered a node's neighborhood is — rather than global position.

With either encoding concatenated onto the node features, attention weights can now be a function of graph structure, not just raw feature similarity — the encodings are what let a node "know" the shape of the graph around it before attention ever runs.

The GraphGPS recipe: message passing + attention, per layer

Rather than choosing between local message passing and global attention, Rampášek et al.'s GraphGPS framework (2022) runs both in every layer: a standard sparse message-passing block (any of GCN/GAT/GraphSAGE/GIN-style updates) alongside a global attention block, with their outputs combined before the next layer. Positional and structural encodings are computed once up front and fed to both blocks. The result is a modular "recipe" rather than one fixed architecture — swap in whichever message-passing layer and whichever efficient attention variant suits the task.

Analogy: This is the same move as a Vision Transformer patchifying an image and adding positional embeddings before running full attention — ViT throws away the CNN's built-in locality prior and re-derives useful structure from data plus explicit position information instead. Graph transformers make the identical trade for graphs: give up hard-wired locality, buy it back (partially) with positional/structural encodings and, in hybrid designs like GraphGPS, a parallel message-passing path.

Trade-offs against message-passing GNNs

Message-passing GNN Graph transformer
Receptive field grows one hop per layer (Lesson 5) Global receptive field from the first layer
Prone to over-smoothing and over-squashing with depth (Lesson 6) Sidesteps both — distant nodes exchange information in one step, not through a narrow multi-hop bottleneck
O(|E|) cost per layer — scales with sparsity O(n²) cost per layer for full attention; needs sparsification or linear-attention tricks to scale
Locality is a hard architectural bias (only real edges matter) Locality is a soft hint from positional/structural encodings, not enforced

"Over-squashing" here is the same bottleneck problem raised in Lesson 6's over-smoothing discussion, seen from a different angle: as a message-passing GNN gets deeper, information from a distant node has to travel through an exponentially growing set of paths and gets compressed into fixed-size vectors along the way, distorting long-range signals. A graph transformer's global attention doesn't need depth to reach far-away nodes, so it doesn't inherit that particular failure mode — at the price of losing the hard locality bias that made sparse message passing cheap and, for many tasks, a genuinely useful inductive bias rather than a limitation to route around.

Key idea: Graph transformers don't strictly dominate message-passing GNNs. They swap one set of failure modes (over-smoothing, over-squashing, limited receptive field) for another (quadratic cost, weaker locality bias, dependence on the quality of the positional/structural encoding). Which one wins is task- and graph-size-dependent — exactly the kind of judgment call the architecture-comparison framework from Lesson 11 should now extend to cover.

Check your understanding

1. Without any positional or structural encoding, what does a Transformer's self-attention over a node set effectively reduce to?

  • A permutation-equivariant function over sets
  • A permutation-equivariant function over grids
  • A permutation-equivariant function over paths
  • A permutation-equivariant function over trees
With no positional or structural information, attention weights depend only on feature similarity, not on the edge set. The resulting function is equivariant to permuting the node set but blind to graph structure — equivalent to a DeepSets-style set function, strictly weaker than 1-WL.

2. What is the main computational trade-off graph transformers make for a global receptive field from layer one?

  • Quadratic cost in node count
  • Quadratic cost in edge count
  • Quadratic cost in layer count
  • Quadratic cost in batch count
Full attention connects every pair of nodes, so a single layer costs O(n²) rather than the O(|E|) of sparse message passing — the price for reaching every node in one step instead of one hop per layer.

3. Why can graph transformers avoid the over-squashing that troubles deep message-passing GNNs?

  • Every node attends to all nodes
  • Every node attends to one neighbor
  • Every node attends to its cluster
  • Every node attends to a subset
Over-squashing comes from information having to travel through an exponentially growing, narrowing set of multi-hop paths as depth increases. Full attention lets any two nodes exchange information directly in a single layer, so there's no long path for that information to be squashed through.

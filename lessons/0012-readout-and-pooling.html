Lesson 12

Readout and Pooling for Graph-Level Tasks

After L rounds of message passing, every node v holds an embedding hv(L) that summarizes its L-hop receptive field. For node- and edge-level tasks, that's the whole story: feed hv (or a pair hu, hv) straight into an output head. But a graph-level task — is this molecule toxic? will this transaction network be flagged? — needs exactly one vector per graph. Lesson 1 promised "we'll cover this in a later lesson." This is that lesson.

From a set of nodes to a graph

Readout (also called graph pooling) is a function that maps the set of final node embeddings {hv : v ∈ V} to a single vector hG. It has one hard requirement, and it isn't new: hG must be permutation invariant, not merely equivariant. A graph has no canonical node order (Lesson 1, Lesson 4), so relabeling the nodes and re-running readout must produce the identical hG — not a permuted version of it, the same vector. Every option below is built to satisfy that constraint by construction: they all treat {hv} as an unordered multiset.

Simple readout: sum, mean, max

The three workhorse readouts, each applied dimension-by-dimension across all nodes in the graph:

  • Sum: hG = ∑v∈V hv
  • Mean: hG = (1/|V|) ∑v∈V hv
  • Max: hG = elementwise maxv∈V hv

All three are cheap, differentiable, and add zero parameters. But they aren't interchangeable:

  • Sum is sensitive to |V|: a graph with twice as many nodes of the same "type" produces roughly twice the magnitude. That's a feature, not a bug, when graph size itself is informative (a bigger molecule has more atoms to be toxic with).
  • Mean normalizes size out. Useful when you care about the average composition of a graph regardless of how big it is, but it can wash out the signal from a small number of decisive nodes in a large graph.
  • Max keeps only the single most extreme value per feature dimension across all nodes — good for "does this graph contain a motif with property X anywhere," bad if the task needs a holistic profile rather than a peak.
Key idea: The GIN paper (Lesson 10) makes this precise: under mild conditions, sum is the only one of the three that is injective over multisets of node embeddings — two different multisets are (almost) guaranteed to sum to different vectors, while mean and max can collide on genuinely different inputs. That's exactly why GIN pairs a sum-aggregator in its message-passing step with a sum-readout at the graph level: injectivity all the way through is what lets GIN match the Weisfeiler-Leman test's discriminative power (more on this in Lesson 15).

In practice, readout has to cooperate with batching (Lesson 2): a batch is one big disjoint-union graph plus a batch vector recording which original graph each node belongs to. Readout becomes a scatter operation — sum/mean/max each node's embedding into the slot given by its batch index, producing one hG per graph in the batch in a single pass. This is exactly what PyTorch Geometric's global_add_pool, global_mean_pool, and global_max_pool do under the hood.

Where flat readout falls short

All three simple readouts treat the final-layer embeddings as an unstructured bag: every node contributes to hG exactly once, exactly the same way, regardless of where it sits in the graph. But many real graphs have structure above the node level — a molecule is built from functional groups, a social network from communities, a fraud ring from tightly-connected clusters loosely linked to the rest of the account graph. A single flat pooling step at the very end has no way to represent "these fifteen nodes form one unit, and that unit relates to these other units."

Hierarchical pooling: DiffPool

DiffPool (Ying, You, Morris, Ren, Hamilton & Leskovec, "Hierarchical Graph Representation Learning with Differentiable Pooling", NeurIPS 2018) takes the CNN analogy from Lesson 1 further: instead of pooling once at the end, coarsen the graph progressively across several layers, the way a CNN shrinks spatial resolution with each pooling layer.

At each pooling layer l, two GNNs run in parallel over the current (already-coarsened) graph:

  • One produces ordinary node embeddings Z(l), same as any message-passing layer.
  • The other produces a soft cluster-assignment matrix S(l) ∈ ℝnl × nl+1 — each row softmax-normalized, so every node gets a distribution over the next layer's (smaller number of) clusters, rather than a hard 0/1 assignment.

The graph is then coarsened using both: X(l+1) = S(l)⊤Z(l) (each new cluster's features are a weighted sum of its member nodes' embeddings), and A(l+1) = S(l)⊤A(l)S(l) (each new cluster-to-cluster edge weight is aggregated from the edges between their members). Repeat for a handful of layers until only one cluster remains — that final vector is hG, no separate readout call needed.

Key idea: DiffPool is trained end-to-end with the rest of the network via ordinary backprop — the cluster assignments are learned jointly with everything else, not computed by a separate graph-clustering algorithm (e.g. spectral clustering) run as a preprocessing step. In practice it's trained with two auxiliary terms: a link-prediction-style reconstruction loss (encouraging S(l)S(l)⊤ to resemble the real adjacency A(l), so clusters respect actual connectivity) and an entropy regularizer (pushing each row of S(l) toward one-hot, so assignments stay interpretable rather than diffuse).
Analogy: DiffPool's learned cluster assignment does for graphs what a strided pooling layer does for a CNN feature map — shrinking the representation while keeping locally-salient structure. The difference is that a CNN's pooling windows are handed to it for free by the fixed grid; DiffPool has to learn which nodes belong together, because graphs don't come with a fixed neighborhood shape to slide a window over.

DiffPool isn't the only hierarchical option — lighter-weight alternatives like top-k / SAGPool score each node with a learned function and simply drop the lowest-scoring fraction, avoiding the dense S(l)S(l)⊤ computation. The soft-assignment idea above is the one worth having internalized, though: it's the "next level up" from flat readout that the rest of the literature riffs on.

Check your understanding

1. GIN's authors argue that one readout function is best able to distinguish graphs that differ only in node count (multiset cardinality), because it isn't normalized by node count. Which one?

  • Sum pooling
  • Mean pooling
  • Max pooling
  • Softmax pooling
Sum scales with |V|, so it's sensitive to node count. Mean explicitly normalizes count out, and max keeps only one extreme value regardless of how many nodes produced it — both lose count information that sum preserves.

2. What problem does DiffPool address that flat sum/mean/max readout does not?

  • It captures the graph's community structure
  • It captures the graph's node features
  • It captures the graph's edge weights
  • It captures the graph's degree sequence
Flat readout already operates on node embeddings (which encode features and, indirectly, local structure) — what it can't represent is that groups of nodes form higher-level units. DiffPool learns soft cluster assignments across several coarsening layers to capture exactly that hierarchical/community structure.

3. During graph batching, what tells the readout step which nodes belong to which original graph?

  • The node feature matrix
  • The edge index tensor
  • The batch index vector
  • The dense adjacency matrix
Batching (Lesson 2) disjoint-unions the graphs and keeps a separate batch vector recording each node's source graph. Readout uses that vector to scatter-sum/mean/max nodes into the correct per-graph slot, since the node and edge tensors alone don't carry graph membership.

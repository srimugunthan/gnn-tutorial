Lesson 9

GAT: Attention on Graphs

GCN weighs neighbors by degree. GraphSAGE's mean and pooling aggregators weigh sampled neighbors equally, or independently through a shared MLP before a symmetric max. Neither ever asks: given what this specific neighbor's features actually say, how much should I trust it? The Graph Attention Network (GAT), from Veličković et al. (2018), answers that question by borrowing the attention mechanism you already know from sequence models and applying it edge by edge.

The limitation it solves: structural weights ignore content

GCN's aggregation weight between nodes i and j is D̃ii−1/2D̃jj−1/2 — fixed the moment you know the graph's degree sequence, regardless of what hi and hj actually contain. Two neighbors with identical degree get identical weight, even if one is far more relevant to the node's task than the other. This is a real cost: in a citation network, not every cited paper is equally informative about a paper's topic; in a transaction graph, not every counterparty is equally informative about whether an account is fraudulent.

Key idea: GAT replaces a structure-determined aggregation weight with a learned, content-dependent one. The weight a node assigns its neighbor is computed from both of their current feature vectors, not just from the graph's topology.

The core mechanism: self-attention over the neighborhood

For every edge (i, j) where j ∈ N(i) (including i itself, via a self-loop, just as in GCN), GAT computes an unnormalized attention score:

Attention coefficient:
eij = LeakyReLU( aT [ Whi ‖ Whj ] )

where W is a shared learned linear transformation applied to every node's features, ‖ is vector concatenation, and a is a single learned attention vector (shared across all nodes and edges) that scores how compatible the pair (Whi, Whj) is.

These raw scores aren't comparable in scale across different neighborhoods, so they're normalized with a softmax over each node's neighbor set — exactly the aggregation step from Lesson 4, now with learned rather than fixed weights:

Normalized attention weight:
αij = softmaxj(eij) = exp(eij) / Σk∈N(i) exp(eik)

hi' = σ( Σj∈N(i) αij Whj )

Notice the shape: this is still gather → aggregate → update. What changed is only how the aggregation weights are produced — a learned function of content, instead of a fixed function of degree.

Worked example: attention weights on a 3-node star

Take a toy case with 1-dimensional transformed features for clarity: node i has Whi = 1.0, and two neighbors j (Whj = 0.5, feature-aligned with i) and k (Whk = −0.5, feature-opposed to i). Suppose the learned attention vector reduces to simply summing the pair (a = [1, 1]), and self-loops are included:

e_ii = LeakyReLU(1.0 + 1.0)  = 2.0    (self-loop)
e_ij = LeakyReLU(1.0 + 0.5)  = 1.5
e_ik = LeakyReLU(1.0 + -0.5) = 0.5

softmax([2.0, 1.5, 0.5]) → α_ii ≈ 0.547, α_ij ≈ 0.331, α_ik ≈ 0.122

Multi-head attention

A single attention mechanism can be unstable to learn and limited in what relationships it can capture, so GAT runs K independent attention heads in parallel, each with its own Wk and ak. At hidden layers, their outputs are concatenated:

h_i' = ‖_{k=1}^{K} σ( Σ_{j∈N(i)} α_ij^k W^k h_j )

At the final output layer, concatenation would multiply the output dimension by K, which usually isn't what you want for a prediction head, so the heads are averaged instead:

h_i' = σ( (1/K) Σ_{k=1}^{K} Σ_{j∈N(i)} α_ij^k W^k h_j )
Analogy: Multi-head attention here plays the same role it does in a Transformer: each head can specialize in a different notion of "relevance" (one head might key off feature similarity, another off something else entirely), and concatenating hidden-layer outputs lets downstream layers combine those perspectives, exactly as multi-head self-attention does over tokens.

What's new, and why it's efficient too

Two properties worth naming explicitly:

  • No graph-global computation. Unlike the spectral derivation behind GCN, GAT's attention mechanism is defined purely locally — a is shared, but it's applied identically to every edge without reference to the graph's eigenstructure, degree matrix, or size. This also makes it naturally parallelizable across edges.
  • Shared, graph-agnostic parameters. W and a don't depend on which node or graph they're applied to — only on the pair of feature vectors in front of them. That's the same property that made GraphSAGE inductive in Lesson 8, and the GAT paper explicitly validates this: it's tested on the same inductive PPI benchmark as GraphSAGE, in addition to transductive citation-network benchmarks. GAT's transductive-vs-inductive behavior depends on how it's trained and deployed, not on a structural constraint in the layer itself, the way GCN's fixed normalization is.

Check your understanding

1. What information does GCN's fixed normalization ignore that GAT's attention coefficients use?

  • The content of each neighbor's features
  • The degree of each neighbor's node
  • The distance of each neighbor's edge
  • The label of each neighbor's class
GCN's weight D̃ii−1/2D̃jj−1/2 depends only on degree. GAT computes eij from a learned function of Whi and Whj themselves, so two neighbors with the same degree can still receive very different attention weights.

2. Which operation in GAT ensures that a node's attention weights over its neighbors sum to one?

  • The softmax normalization over neighbors
  • The LeakyReLU activation over neighbors
  • The degree normalization over neighbors
  • The mean aggregation over neighbors
LeakyReLU produces the raw, unbounded score eij. The softmax, applied over all of node i's neighbors (including itself via the self-loop), is what turns those raw scores into normalized weights αij that sum to one.

3. Why does GAT average attention heads at the final output layer instead of concatenating them, as it does at hidden layers?

  • Concatenating there would make output dimension head-count dependent
  • Averaging there always improves classification accuracy more substantially
  • Concatenating there would violate the permutation invariance property
  • Averaging there removes the need for a softmax
Concatenating K heads multiplies the representation width by K at every layer, which is fine internally but inconvenient at the final layer, where the output dimension should match the task (e.g. number of classes) rather than scale with the number of attention heads.

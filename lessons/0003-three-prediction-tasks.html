Lesson 3

The Three Prediction Tasks

Lesson 1 introduced three levels of prediction — node, edge, and graph — and deliberately punted on the details: "the architecture stays mostly the same, only the final pooling/readout step changes." Lesson 2 gave you the tensors (X, edge_index) that a GNN actually consumes. This lesson closes the loop: given those tensors, what does the output side of the network look like for each task?

A shared trunk, three different heads

Every GNN we'll study in this course has the same basic shape. A stack of message-passing layers (the mechanics are Lesson 4's subject) transforms the raw node features X into learned node representations. We'll call these hi — the hidden state, or embedding, of node i — to distinguish them from the raw input feature xi they started as. After L layers, every node i has an embedding hi that encodes not just its own features but information gathered from its local neighborhood.

What happens next is where node-, edge-, and graph-level tasks diverge. The encoder (the message-passing stack) is shared; only the head bolted onto the end changes.

Node-level: classify what's already there

If the target is a property of individual nodes — is this account fraudulent, which faction does this club member join, what part of speech is this token — the answer is already sitting at each node after L layers. You take hi and pass it through a shared classifier (typically a small MLP or even a single linear layer) to get a per-node prediction:

y_i = MLP(h_i)   # applied independently to every node i
Key idea: Node classification needs no pooling step at all. The same classifier head is applied node-by-node, weight-shared exactly the way a CNN's final 1×1 convolution is applied pixel-by-pixel. This is the simplest of the three heads — everything interesting already happened inside the message-passing layers.

Edge-level: a pairwise scoring function

Link prediction — will these two nodes connect? what's the type of this relationship? — needs to combine two node embeddings into one prediction. This introduces something node classification never needed: a function that takes a pair of embeddings and produces a score.

y_ij = score(h_i, h_j)

# common choices for score():
#   dot product:      score(h_i, h_j) = h_i · h_j
#   concat + MLP:      score(h_i, h_j) = MLP([h_i ; h_j])
#   bilinear:          score(h_i, h_j) = h_i^T W h_j

The score is usually squashed through a sigmoid to get a probability that the edge exists, then trained against known edges (positive examples) and sampled non-edges (negative examples) — a detail we'll return to when we cover training strategies in Lesson 13.

Analogy: This is structurally the same move as a Siamese network comparing two embeddings for similarity, or the query·key dot product inside attention. The GNN's job is just to produce embeddings good enough that a simple pairwise function on top of them is informative.

Graph-level: everyone gets a vote

Graph classification — is this molecule toxic, will this program crash — needs a single vector representing the whole graph, but the encoder only ever produced one embedding per node, and graphs vary in node count. Something has to compress a variable-size set {h1, …, hn} into one fixed-size vector before a classifier can touch it. That compression step is called readout (or pooling):

h_G = READOUT({h_i : i in V})     # e.g. sum, mean, or max over all nodes
y_G = MLP(h_G)

The simplest readouts are exactly the permutation-invariant aggregators you'd guess from Lesson 1's equivariance discussion — sum, mean, max over all node embeddings. More expressive options (attention-weighted pooling, hierarchical pooling that clusters nodes first) exist and get their own full treatment in Lesson 12; for now, the important point is structural, not which specific readout you pick.

Key idea: Graph-level prediction is the only one of the three tasks that strictly requires a permutation-invariant aggregation over all nodes. Node and edge tasks only ever need permutation-equivariant per-node or per-pair operations — recall the equivariant/invariant distinction from Lesson 1's glossary entries.

Same tensors, different labels

Tying this back to Lesson 2's plumbing: the input tensors (X, edge_index) are identical across all three tasks. What differs is only the shape of the training label and which head sits on top of the shared encoder:

Task Label shape Head Pooling?
Node classification one label per node MLP(hi) No
Link prediction one label per node pair score(hi, hj) No
Graph classification one label per graph MLP(READOUT(H)) Yes

Check your understanding

1. A GNN scores the fraud risk of every individual account node in a transaction graph. Which output-layer design fits this task?

  • Per-node MLP, no pooling
  • Graph-level MLP after pooling
  • Pairwise scorer over embeddings
  • Global readout then softmax
Fraud risk per account is a node-level target, so each node's embedding is passed through a shared classifier directly. No pooling step is involved — that's only needed once the target is a property of the whole graph.

2. Which output-head design is distinctive to link prediction, and not needed for node or graph classification?

  • A pairwise node-embedding scorer
  • A per-node softmax classifier
  • A permutation-invariant readout function
  • A stack of MLP layers
Link prediction combines two node embeddings (via a dot product, bilinear form, or concatenation into an MLP) into a single score for whether an edge exists. Neither the node head nor the graph head needs this pairwise combination step.

3. Predicting overall molecule solubility from atom-level embeddings requires which step that node classification skips entirely?

  • A readout that pools nodes
  • A pairwise edge score function
  • A shared per-node linear layer
  • A larger node feature matrix
Graph-level tasks must compress a variable number of node embeddings into one fixed-size graph vector via a permutation-invariant readout (sum, mean, max, or something fancier — Lesson 12) before the final classifier can run. Node classification never needs this compression.

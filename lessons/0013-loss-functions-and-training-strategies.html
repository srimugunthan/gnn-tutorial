Lesson 13

Loss Functions and Training Strategies

Lessons 4–11 built the encoder: message passing, receptive fields, and the GCN/GraphSAGE/GAT/GIN family. Lesson 12 finished it off with readout for graph-level outputs. The encoder is fully specified — but wrapping a training loop around it is where an ML-experienced practitioner is most likely to get tripped up, because graphs quietly break the i.i.d. assumption almost every standard training pipeline is built on.

The losses themselves are familiar

Nothing new here, so we'll be brief: node classification uses per-node cross-entropy (masked to whichever nodes have labels); graph classification uses cross-entropy on the pooled hG from Lesson 12; regression tasks use MSE at whichever level applies. Optimizers, learning rate schedules, regularization — all the same tools from your CNN/RNN experience transfer directly. The graph-specific work is entirely in what data reaches the loss, not in the loss function's form.

Transductive training: the same graph, in and out

Recall the transductive-vs-inductive distinction that's been threaded through the architecture lessons. In a transductive node-classification setup — the classic Cora / Citeseer / Pubmed benchmarks the original GCN paper reports on — there is one fixed graph, and the train, validation, and test node sets are all subsets of its nodes. Critically, all of them are present in the graph during training: their features and their edges are visible to every message-passing step, every epoch. Only their labels are hidden from the loss via a mask.

This is a fundamentally different shape from an i.i.d. tabular or image split, where test rows are physically absent from the training data entirely. A GNN training on a transductive split is, on every forward pass, aggregating information that flows through test nodes' features and edges — it just never gets gradient signal from their labels.

Key idea: "Transductive" does not mean "no leakage risk." It means the leakage boundary has moved from features and structure (safely shared) to labels only (must stay masked). Masking labels correctly is necessary but not automatically sufficient — the next section shows a case where structure itself has to be masked too.

This also isn't just an evaluation-protocol footnote for your AML/fraud interest. A fraud graph gains new accounts and transactions constantly; the transductive assumption — that the full node set is fixed and known ahead of time — breaks on day one of deployment. That's the practical reason GraphSAGE-style inductive aggregation (Lesson 8) matters operationally, not just as an architecture-comparison talking point.

Splitting edges for link prediction without leaking the answer

Link prediction has a subtlety node classification doesn't: the thing being predicted — "does an edge exist between u and v?" — is also part of the input that message passing consumes. If you train on the full adjacency matrix and then ask the model to score a training edge, a 1-layer GNN can simply "see" that edge directly in u and v's own neighborhoods and answer correctly for the wrong reason. The model looks like it's learned to predict links; it has actually learned to look up an entry it was already given.

The fix is to partition edges into disjoint roles before anything else happens:

  • Message-passing edges: the adjacency the encoder actually convolves over to produce embeddings.
  • Supervision edges: the positive examples the loss trains on — drawn from edges deliberately excluded from the message-passing set above.
  • Held-out validation/test edges: excluded from training-time message passing and from the training loss entirely.
Key idea: The edge you're training the model to predict must never be one it can also convolve over in that same training step. Libraries like PyTorch Geometric bake this discipline in — its RandomLinkSplit utility produces exactly these disjoint message-passing / supervision / test edge sets rather than a single naive edge shuffle.

Negative sampling

A graph only records positive facts: an edge that exists. To turn "does this edge exist?" into a trainable classification or ranking loss, you need negative examples too — node pairs with no edge between them — and the graph doesn't hand those to you directly.

Negative sampling manufactures them: for each positive edge (u, v), sample one or more node pairs that are not edges — commonly by fixing u and drawing a random v′ not in u's neighbor set. The ratio of negatives to positives per positive edge is a tunable hyperparameter, same as it would be for any imbalanced binary classification setup. Two loss shapes are standard once you have them: binary cross-entropy on sigmoid(score(u,v)) treating positive/negative as classes, or a margin/ranking loss such as Bayesian Personalized Ranking (BPR), which only asks that score(positive) exceed score(negative) by some margin rather than pinning down an absolute probability.

One detail worth internalizing: negatives should be resampled every training epoch (so the model can't just memorize one fixed negative set), but fixed once for validation and test (so the reported metric is comparable run to run, rather than drifting because the negative pairs changed).

Self-supervised objectives when labels are scarce

Labeled nodes or edges are frequently a tiny fraction of a real graph — a handful of confirmed fraud accounts out of millions, say. Self-supervised pretraining lets you exploit the graph's full structure and features with no labels at all, then fine-tune (or just train a lightweight classifier on top of frozen embeddings) using the scarce labeled subset.

Link prediction itself, described above, is one such self-supervised pretext task — it needs no labels beyond the graph's own edges. A more general contrastive alternative is Deep Graph Infomax (DGI; Veličković et al., arXiv:1809.10341, ICLR 2019): it trains the encoder to maximize agreement between each node's local embedding and a global graph summary vector (computed via the same kind of readout from Lesson 12), while minimizing agreement with a summary computed from a corrupted version of the graph (e.g. node features randomly shuffled across nodes) used as the negative signal. No labels enter the loss at all — only the graph's own structure and features, contrasted against a deliberately-broken version of itself.

Analogy: DGI is the graph analogue of contrastive pretraining in vision (SimCLR-style: pull together representations of two augmented views of the same image, push apart representations of different images). Swap "augmented view" for "corrupted graph," and "two images" for "a node's local embedding vs. the whole graph's summary," and it's the same recipe: agree with your true context, disagree with a shuffled decoy.

DeepWalk and node2vec (next lesson) are the historical predecessors of this idea — self-supervised objectives that also need no labels, just predating the contrastive-with-a-GNN-encoder framing DGI uses.

Check your understanding

1. In a transductive node-classification setup on a single citation graph, what is actually hidden from the model during training?

  • Only the test node labels
  • Only the test node features
  • Only the test node edges
  • The entire test subgraph structure
Transductive training keeps the full graph — features and edges of every node, including test nodes — visible during every forward pass. A mask hides only the test labels from the loss, which is a much narrower boundary than an i.i.d. split where test rows are absent entirely.

2. If test edges remain in the message-passing graph during link-prediction training, what happens?

  • The model directly observes answers
  • The model trains far slower
  • The model ignores all edges
  • The model cannot use features
A GNN convolving over an edge it's also being asked to predict can simply "see" that edge in its own receptive field and answer correctly without learning to generalize. That's why message-passing, supervision, and held-out edges must be kept in disjoint sets.

3. Why is negative sampling necessary when training a link-prediction model?

  • Graphs only contain positive edge examples
  • Graphs only contain negative edge examples
  • Positive edges are always mislabeled data
  • Negative edges speed up gradient computation
A graph records only edges that exist — there is no built-in list of "non-edges." Negative sampling manufactures node pairs with no edge so the loss has something to contrast the true edges against, turning link prediction into a trainable binary classification or ranking problem.

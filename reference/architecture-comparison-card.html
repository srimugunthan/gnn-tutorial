Architecture Comparison Card

Side-by-side comparison of the four architectures from Module 3 (Lessons 7–10). Read the row before the column: each row is one dimension of comparison across all four architectures, not a summary of one architecture alone.

Dimension GCN GraphSAGE GAT GIN
Aggregation type Normalized weighted sum over 1-hop neighbors + self-loop Sampled neighbor aggregation (mean / LSTM / max-pool), concatenated with self Attention-weighted sum over 1-hop neighbors + self-loop, multi-head Sum over 1-hop neighbors + learnable self-weight, then MLP
Neighbor weighting Fixed, structure-only: D̃−1/2ÃD̃−1/2 Fixed/uniform among a sampled subset (mean), or MLP+max-pool per neighbor Learned, content-dependent: softmax over LeakyReLU attention scores Uniform (unweighted sum); expressive power comes from injectivity, not per-neighbor weighting
Transductive vs. inductive Transductive by default — propagation rule is tied to one fixed graph's D̃ and Ã Inductive by design — learns aggregator functions, not per-node embeddings Works in both settings; validated on transductive citation nets and the inductive PPI benchmark Inductive by construction; typically applied to graph-level tasks where every graph is unseen at test time
Expressiveness Below WL — degree-weighted sum is not injective over neighbor multisets Below WL for mean/max variants — both provably lose count/distribution information Below WL in the worst case — attention-weighted sum is not proven injective WL-equivalent — provably the most expressive standard message-passing GNN (Xu et al., 2019)
Typical use case Node classification on a single, mostly-static graph (e.g. citation networks) Large-scale or growing graphs; settings needing to embed new nodes without retraining Tasks where neighbor relevance varies sharply, or edge-level interpretability is wanted Graph classification needing fine-grained structural discrimination (e.g. molecules)
Key limitation No native path for unseen nodes; ignores neighbor content; over-smooths with depth Sampling adds variance; mean/pool aggregators still don't differentiate neighbor content More compute per layer (attention over every edge); not guaranteed to beat GCN's expressiveness ceiling Still bounded by the WL test; sum aggregation is sensitive to neighbor-count scale
Key idea: Read this table by row, not just by column. Each row is a genuinely different design axis (weighting mechanism, generalization, theoretical power) — an architecture that scores well on one axis doesn't automatically score well on another. GAT's learned attention doesn't buy WL-level expressiveness; GIN's WL-level expressiveness doesn't come from smarter weighting at all.
